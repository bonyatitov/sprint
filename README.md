# Планировщик спринта

Веб-приложение, которое равномерно распределяет часы занятий (курс и
дополнительные темы) на спринт из нескольких недель, учитывая рабочий
график, дни отдыха и возрастные ограничения по нагрузке. Все данные
хранятся локально в браузере пользователя (localStorage) — сервер не
нужен, бэкенда нет.

## Возможности

- **Занятия** — курс и дополнительные темы с часами на весь спринт;
  дополнительные темы подключаются к расписанию по очереди, а не все сразу.
- **Параметры спринта** — дата начала, длительность в неделях, выходные дни.
- **Рабочий график** — ручная отметка рабочих дней или готовые паттерны
  5/2, 2/2, сутки/трое; для 5/2 занятия по вечерам не пропадают, а только
  сокращаются.
- **Умное распределение нагрузки** — ограничивает число занятий в день по
  возрасту и разгружает день после рабочей смены.
- **Помодоро-таймеры** — отдельный таймер работы/отдыха на каждое занятие,
  устойчивый к фоновым вкладкам браузера.
- **Заметки** — короткая заметка на каждое занятие в конкретный день, с
  отдельной страницей со всеми заметками спринта.
- **Резервная копия** — экспорт/импорт всего состояния в JSON-файл, чтобы
  не потерять прогресс при очистке кеша браузера.
- **Страница «Инструкция»** — краткое руководство по всем разделам прямо в
  приложении (`/help`).

Стек: Vite, React 19, TypeScript, HeroUI v3, Tailwind CSS v4.

## Локальная разработка

```bash
npm install
npm run dev
```

Прочие команды: `npm run build` (типы + прод-сборка), `npm run lint`,
`npm run preview`.

## Деплой на сервер (ВПС, Docker)

Приложение полностью статическое (SPA) — контейнер собирает прод-бандл и
раздаёт его через Nginx с fallback на `index.html` для клиентского
роутинга (`/notes`, `/help`).

На ВПС нужен установленный Docker и Docker Compose.

```bash
git clone <адрес репозитория>
cd sprint-planner
docker compose up -d --build
```

По умолчанию приложение будет доступно на порту `8080` (см.
`docker-compose.yml`, маппинг `"8080:80"` — при необходимости замените
порт слева на нужный) — то есть `http://<ip-впс>:8080`.

Для обновления после изменений в коде:

```bash
git pull
docker compose up -d --build
```

Если приложение должно отдаваться по HTTPS на реальном домене, поставьте
перед контейнером обратный проксирующий Nginx/Caddy на хосте (или
добавьте Traefik/Certbot) — сам контейнер отдаёт только plain HTTP на
порту 80.

Собрать и запустить без Compose:

```bash
docker build -t sprint-planner .
docker run -d --name sprint-planner -p 8080:80 --restart unless-stopped sprint-planner
```
