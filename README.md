# Планировщик спринта

Веб-приложение, которое равномерно распределяет часы занятий (курс и
дополнительные темы) на спринт из нескольких недель, учитывая рабочий
график, дни отдыха и возрастные ограничения по нагрузке. Все данные
хранятся локально в браузере пользователя (localStorage) — сервер не
нужен, бэкенда нет.

## Возможности

- **Занятия** — курс и дополнительные темы с часами на весь спринт;
  дополнительные темы подключаются к расписанию по очереди, а не все сразу.
- **Параметры спринта** — дата начала, длительность в неделях, выходные дни.
- **Рабочий график** — ручная отметка рабочих дней или готовые паттерны
  5/2, 2/2, сутки/трое; для 5/2 занятия по вечерам не пропадают, а только
  сокращаются.
- **Умное распределение нагрузки** — ограничивает число занятий в день по
  возрасту и разгружает день после рабочей смены.
- **Помодоро-таймеры** — отдельный таймер работы/отдыха на каждое занятие,
  устойчивый к фоновым вкладкам браузера.
- **Заметки** — короткая заметка на каждое занятие в конкретный день, с
  отдельной страницей со всеми заметками спринта.
- **Резервная копия** — экспорт/импорт всего состояния в JSON-файл, чтобы
  не потерять прогресс при очистке кеша браузера.
- **Страница «Инструкция»** — краткое руководство по всем разделам прямо в
  приложении (`/help`).

Стек: Vite, React 19, TypeScript, HeroUI v3, Tailwind CSS v4.

## Локальная разработка

```bash
npm install
npm run dev
```

Прочие команды: `npm run build` (типы + прод-сборка), `npm run lint`,
`npm run preview`.

## Деплой на сервер (ВПС, Docker)

Приложение полностью статическое (SPA) — контейнер собирает прод-бандл и
раздаёт его через Nginx с fallback на `index.html` для клиентского
роутинга (`/notes`, `/help`).

На ВПС нужен установленный Docker и Docker Compose.

```bash
git clone <адрес репозитория>
cd sprint-planner
docker compose up -d --build
```

Порт `8080` привязан только к `127.0.0.1` (см. `docker-compose.yml`) —
снаружи по IP ВПС приложение не открывается, доступ к нему есть только у
процессов на самом сервере. Чтобы отдать приложение наружу под доменом и
HTTPS, настройте reverse-proxy на хосте — см. раздел «Домен и HTTPS»
ниже.

Для обновления после изменений в коде:

```bash
git pull
docker compose up -d --build
```

Собрать и запустить без Compose:

```bash
docker build -t sprint-planner .
docker run -d --name sprint-planner -p 127.0.0.1:8080:80 --restart unless-stopped sprint-planner
```

## Домен и HTTPS (Nginx + Certbot на хосте)

Контейнер отдаёт только plain HTTP на порту 8080, привязанном к
`127.0.0.1` — сам домен и HTTPS настраиваются reverse-proxy'ем на хосте
ВПС, а не в контейнере.

1. У DNS-провайдера домена добавьте A-запись `sprint.bonya-dev.ru` →
   IP-адрес ВПС.

2. На сервере установите Nginx и Certbot (если ещё не установлены):

   ```bash
   sudo apt install nginx certbot python3-certbot-nginx
   ```

3. Разверните готовый конфиг из `deploy/nginx-host.conf`:

   ```bash
   sudo cp deploy/nginx-host.conf /etc/nginx/sites-available/sprint.bonya-dev.ru
   sudo ln -s /etc/nginx/sites-available/sprint.bonya-dev.ru /etc/nginx/sites-enabled/
   sudo nginx -t && sudo systemctl reload nginx
   ```

4. Выпустите сертификат — Certbot сам допишет блок `listen 443 ssl` в
   этот конфиг и настроит автообновление сертификата по cron/systemd-таймеру:

   ```bash
   sudo certbot --nginx -d sprint.bonya-dev.ru
   ```

5. Откройте порты 80 и 443 в файрволе (например `sudo ufw allow 80,443/tcp`).
   Порт 8080 наружу открывать не нужно — контейнер слушает только
   `127.0.0.1:8080`, доступ к нему есть только у Nginx на этом же хосте.
